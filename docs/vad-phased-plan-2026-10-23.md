# Voxly VAD 分步接入计划

日期：2026-10-23。本文是本地工作区的执行计划，不代表已发布版本的能力。

## 第一阶段：独立对照试验

状态：试验入口已实现，针对性检查通过；已完成约 21 分 35 秒真实访谈全长对照。自动模式在 02:16.370–02:21.602 出现韩文，中文提示局部复测已输出中文；尚未完成全场中文模式复测和人工回听验收。

- 保留现有能量阈值／最长 30 秒分段路径。
- 增加显式选择的 Silero VAD 试验路径，使用 sherpa-onnx 1.13.8。
- 模型来自 k2-fsa 官方 Release，643854 字节，SHA-256 为 `9e2449e1087496d8d4caba907f23e0bd3f78d91fa552479bb9c23ac09cbb1fd6`。
- 试验二进制和 VAD 模型存放在忽略目录 `.runtime-build/vad-pilot/`，不替换桌面二进制，不修改用户设置，不创建正式 Task。
- 原始音频只解码一次，两种方法共用同一份 16 kHz 单声道 PCM；保留完整时间轴。
- 试验参数：概率阈值 0.35、结束静音 0.5 秒、最短讲话 0.1 秒、前后各 150 毫秒余量；VAD 软分段目标 20 秒，识别片段硬上限 30 秒。参数尚未由真实会议校准。
- 时间戳是含上下文余量的音频片段边界，不是逐字时间戳，也不是说话人切换时间。

使用已有 SenseVoice 安装运行：

```bash
cd /path/to/meet-asr
python3 scripts/vad_pilot.py "/绝对路径/会议录音.m4a"
```

默认使用 `--language zh`。多语种录音可以显式传入 `--language auto`；没有根据识别文字猜测语言并自动切换的规则。中文提示在中英拼接样音中保留了英文，但这不是任意多语种混说的准确率保证。

脚本首次运行会编译独立试验程序、下载并校验小型 VAD 模型。需要 macOS、Xcode 命令行工具、Python 3 和 ffmpeg；无需 Python 第三方库、云端凭据或联网推理。SenseVoice 文件和 receipt 根据项目目录内的模型 catalog 校验。

输出目录会显示在终端，包含：

- `comparison.md`：耗时、片段数量、文本差异和人工核验提示。
- `baseline.md`、`vad.md`：两种分段方式的全文。
- `vad-timed.md`：带原音时间位置的片段文字。
- `baseline.json`、`vad.json`、`metrics.json`：结构化结果和指标。

建议先用 3–5 分钟真实会议，覆盖轻声、短回应、停顿和噪声。对照听原音，确认字头字尾与最后一句完整。没有人工参考文本时，文本差异不当作错误率。试验目前读取整份解码后的音频，尚非流式内存方案。

已执行的针对性检查：

- 显式 auto 模式在官方中文样音上保持原有输出；默认模式与显式 zh 模式一致。
- 纯静音且文件尾部不足一个 VAD 窗口时，不输出语音或文字。
- 两段样音前后加静音，原时间偏移保留、片段有序且不重叠。
- 文件末尾仍有讲话且不足一个完整窗口时，完成喂入和 Flush，保留末段文字。
- VAD 文件缺失时失败退出，不静默退回旧分段。

检查脚本：

```bash
python3 scripts/check_vad_pilot.py "/官方样音目录/test_wavs/zh.wav"
```

当前将此参数作为可选功能接入。全场人工回听、漏字／切字验收和更长录音资源评估仍待完成，因此不默认启用，不以短样音或单次耗时替代质量验收。

## 第二阶段：接入 Go Task 与恢复

状态：当前工作区已实现，并通过任务级实录检查。

1. 确定并落盘稳定的片段清单，包含片段 ID、原音采样位置、文字、状态和实际模型／运行时／分段参数身份。
2. 保留现有 canonical transcript 和生成内容版本关系；继续输出原有全文，附加时间片段文件。
3. Go 负责任务、路径边界和原子保存，原生程序负责 VAD／识别；不把推理搬进 React。
4. 如沿用外层检查点分块，时间使用实际 PCM 采样位置换算；不可用“分块序号 × 预计时长”推算。处理分块边界的检测器状态或上下文重叠及去重。
5. 恢复使用已保存的片段计划，避免重跑 VAD 后编号改变；确认取消可终止原生进程并保留已提交结果。
6. 无讲话时给出明确状态，不将静音误报成识别失败或凭据缺失。旧任务保持可读，新功能不改变云端 ASR 路径。

只运行对应的原生、Go 任务／恢复检查，不要求无关全量回归。

## 第四阶段：CAM++ 说话人区分

状态：2026-10-26 已预留 Go 接口，模型和处理链路尚未接入。

`core-go/diarization.go` 定义 `SpeakerDiarizer` 边界：接收原时间轴上的规范化 PCM WAV 和 VAD 讲话区间，返回匿名说话人区间及模型／聚类参数身份。说话人区间独立于 VAD／ASR 切片，允许一段切片内换人；不会提前把一个 VAD 段等同于一个说话人。当前没有实现、注册、下载、模型调用、持久化字段或桌面开关，现有输出格式与转写流程不变。

未来接入时仍需实现声纹提取和聚类、结果校验、文字对齐、原子保存、取消／恢复与清理保护。已启用的说话人处理必须在“仅保留文本”删除音频之前完成并校验结果；不能仅靠接口承诺这些行为。已经删掉全部音频的旧任务无法补做，除非重新提供音频。

在时间片段之上接入声纹模型，进行全场一致的聚类，并处理连续讲话中的说话人变化。VAD 段不假设只有一个说话人。第一版只承诺匿名说话人标签，不承诺自动姓名识别或重叠讲话拆分。
